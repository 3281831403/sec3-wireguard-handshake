握手报文里的发起时间戳被原样重放，接收端当成新会话又建了一条隧道：同一份旧报文会反复触发新握手，隧道数量随重放次数增长，资源被持续占用。握手必须携带单调递增的时间戳，任何不新于已接受值的时间戳都必须拒绝；发起报文与响应报文必须绑定同一个会话标识；密钥材料必须验证消息认证值；重放窗口必须随时间滑动；对端公钥必须落在允许集合之内；批量校验时每一条报文都必须独立判断。不变量只有两条：同一握手报文不可能被接受两次；时间戳回退必然被拒绝。
